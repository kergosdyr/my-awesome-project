# Lab 운영 규칙

## 브랜치는 실험 노트다

`main`은 안정적인 비교군이고 `lab/<topic>`은 질문 하나를 검증하는 작업 공간입니다. 예정된 주제는 Issue로 관리하고 실제 구현을 시작할 때만 브랜치를 만듭니다.

```bash
git switch main
git pull --ff-only
git switch -c lab/cache-stampede
cp docs/labs/_template.md docs/labs/cache-stampede.md
```

## 한 실험의 완료 조건

- 질문과 반증 가능한 가설이 있다.
- 기준 commit/tag와 변경 전 원시 측정값이 있다.
- 변경 전후 환경, 데이터, warm-up, 요청률이 같다.
- 성능뿐 아니라 정합성과 실패·복구 경로를 검증했다.
- 결과가 기대와 달라도 그대로 기록했다.
- 범용 변경을 `main`에 합칠지, 구현을 결과 tag로만 보존할지 결정했다.

## 결과 보존

작업 중에는 Draft PR을 실험 일지로 사용합니다. 완료 후 무거운 인프라와 대안 구현은 `lab/<topic>-v1` tag로 동결할 수 있습니다. `main`에는 공통 관측성, 재사용 가능한 fixture, 검증된 문서처럼 다음 실험에도 필요한 것만 합칩니다.

## 비교 원칙

- 절대 수치가 아니라 동일 조건의 전후 차이를 해석합니다.
- 평균만 사용하지 않고 p50/p95/p99와 분포를 봅니다.
- 성공 응답 처리량과 전체 요청 처리량을 구분합니다.
- 오류율 감소가 단순 거절 증가에서 나온 것은 아닌지 확인합니다.
- 성능 개선과 정합성 보장을 별개의 결과로 기록합니다.
- 로컬 단일 머신 결과를 운영 용량으로 일반화하지 않습니다.
