# ADR 0001: 안정 기준선과 필요 시 생성하는 lab 브랜치

- 상태: accepted
- 날짜: 2026-08-10

## 결정

`main`은 항상 실행 가능한 커머스 기준선으로 유지한다. 예정된 실험은 Issue와 README roadmap으로 관리하며 실제 측정을 시작할 때만 `lab/<topic>` 브랜치를 생성한다. 완료된 구현은 필요하면 tag로 동결하고, 공통 기반과 결과 문서만 `main`에 반영한다.

## 이유

여러 장기 브랜치를 미리 만들면 기준선 변경과 의존성 업데이트를 각 브랜치에 반복 반영해야 한다. 빈 브랜치는 학습 상태나 검증 증거도 표현하지 못한다. Issue는 예정·진행 상태를, Draft PR은 가설부터 결론까지의 변경 이력을, tag는 재현 가능한 완료 시점을 더 명확하게 표현한다.

## 결과

- 실험 시작 비용은 브랜치와 문서 한 개를 만드는 수준으로 유지된다.
- 서로 충돌하는 기술 선택을 `main`에 누적하지 않는다.
- 오래된 lab을 실행할 때는 tag 시점의 의존성과 환경을 사용해야 한다.
- 공통 보안·빌드 변경을 모든 동결 tag에 소급 적용하지 않는다.
