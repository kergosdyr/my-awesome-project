# 2026-09-14 학습 기록


## Day5 후속 — Backend 피드백과 진행분 보존

사용자는 과제가 단순 구현 같아 의미를 찾기 어렵고, 5분이면 할 것 같지만 설명이 불명확해 하기 싫었으며 전날 피곤해서 중단했다고 말했다. 이는 자기보고이며 소요시간·구현 완료·숙련으로 평가하지 않는다.

실제 코드는 예약 조회·없는 예약 반환·PG 승인 호출까지 작성됐고 receipt.에서 중단돼 있었다. 작성 내용을 보존하고 미완성 표현을 주석으로 남긴 뒤 TODO 예외로 마무리하여 커밋 가능한 컴파일 상태로 정리했다. 업무 정답은 추가하지 않았다.

튜터가 앞서 설명한 PG PROCESSING/APPROVED, 통신 응답 유실, 로컬 PENDING/PAID의 구분을 Java 문제 주석과 README에 반영했다. 첫 요청 내 즉시 재시도 금지는 실습 관찰을 나누는 제약이지 일반적인 설계 정답이 아님을 명시했다. 사용자의 독립 설명 확인은 아직 없다.

B005는 작성 중·보류. 새 Day6 과제나 추가 숙제를 발행하지 않았다. 다음 과제는 업무 맥락·실행 결과·설계 선택 범위를 명확히 하고, Redis/Kafka 추가 자체를 목표로 삼지 않도록 운영 지시를 수정했다.

검증: make check-study(전체 날짜 예제 컴파일, C00510개+제공 인프라4개), make check-blog, make build-blog 통과. B005 업무 완성 검사는 아니며 미구현을 완료로 기록하지 않는다. 사용자 요청에 따라 커머스 정리·블로그 실행 소스·챌린지와 이번 기록을 커밋/푸시 대상으로 묶었다. 별도 Redis 작업, 블로그 초안·QA 자료, 개인 조사 원본은 대상에서 제외했다.
