### Day5 C005 — 첫 접근과 최적화 아이디어 요청

사용자는 코드 작성 전 각 위치의 오른쪽을 이중 반복문으로 검사하는 접근과 O(n²) 복잡도를 제안했다. 이를 정답이 아닐 것이라 추측했고 최적화 아이디어가 떠오르지 않는다며 설명을 요청했다. 코드·실제 시간은 미제출이며 정확한 기본 접근과 복잡도 추론을 코드 통과나 독립 최적화 성과로 확대하지 않는다.

튜터 피드백: 이중 반복문은 기본 정확성을 충족하는 정답이며 O(n) 목표와 구분한다. 현재 값을 이전의 아직 답을 못 찾은 위치와 비교하는 관점, 해결된 위치는 다시 검사할 필요가 없다는 이유를 작은 예로 설명한다. 핵심 풀이 아이디어 도움 제공으로 구분하며 정답 코드는 제공하지 않는다. 후속 적용 질문은 [5,2,4]에서 4를 만났을 때 해결되는 위치와 남는 위치다.

## 통합 복습 답변과 질문 정정

- 1번: 충돌 감소는 단정할 수 없으며 재시도로 오히려 충돌이 많아졌다고 봄. 측정 구분 질문은 이해하지 못했다고 명시.

- 4번: replica·Sentinel은 복제/장애 전환이며 샤딩은 Cluster라고 구분.

튜터 정정: 재시도 증가가 충돌 증가를 필연적으로 뜻하지는 않음. 요청의 첫 충돌·추가 시도·재시도 복구·최종 실패를 구별하는 작은 예로 설명한다. 만료가 즉시 가용 재고에 반영되는 설계라면 예약 해제 목적은 달성할 수 있다. 별도 카운터 반환이 필요한 설계와 구분하지 않은 질문이 불명확했으므로 3번 오답/실패 처리와 간격 초기화를 하지 않는다. 같은 DB의 원자성과 여러 행의 경합 분산은 서로 다른 효과임을 짧게 보완한다.

Shopify 사례 자동 복습은 사용자 반복 부담에 따라 중단한다. 재시도 항목은 부분 기억으로9/14, Redis 구성 역할 항목은3일 간격으로9/16. Saga 만료는 판정 보류하며 명확한 조건을 제시하기 전 재출제하지 않는다. 오늘 추가 꼬리 질문 없음. 자료 사용 여부·시간은 미확인.


### 사용자 정정 — 종료한 프로젝트 복구본도 삭제

사용자는 현재 작업과 관계없는 예전 프로젝트를 따로 보관할 필요가 없으며 삭제하라고 명시했다. 이번 정리에서 만든 약1.4GB 복구 디렉터리(이동한 원본 앱·실험 자료, Git bundle, worktree 압축본 포함)를 영구 삭제하고 경로 부재를 확인했다. 현재 블로그·공부 예제 코드는 변경하지 않았으며 문서의 복구 가능 안내를 삭제 상태로 바로잡았다. Git 커밋 이력 재작성은 수행하지 않았다.
