# AI를 회상 튜터로 사용하는 학습 루프

## 이 노트의 출발점

사용자가 제공한 조사문을 바탕으로 만든 운영 원칙이다. 아직 사용자의 첫 회상 답변은 없으므로, 아래 내용은 학습 결과가 아니라 다음 세션에서 검증할 가설과 질문이다.

## 현재의 한 문장 설명

AI가 내용을 대신 요약하게 하기보다, 먼저 내가 기억을 꺼낸 다음 AI가 오류·누락·trade-off를 지적하고 변형 문제를 내도록 사용한다.

## 의사결정 모델

- 해결하려는 문제: 영상을 많이 보고 요약을 읽어도 실제로 설명하거나 새로운 문제에 적용하지 못하는 상태
- 먼저 확인할 조건: 자료를 보지 않은 첫 회상이 남아 있는가, 원문이나 공식 출처가 있는가, 독립적으로 설명해야 할 목표가 무엇인가
- 기본 선택: 짧게 학습하고 자료를 닫은 뒤 회상 → 자기 설명 → 튜터 피드백 → 변형 문제 → 간격 복습
- 선택하지 않을 조건: 단순한 검색, 용어 확인, 원문 압축 자체가 최종 목적인 작업
- 주요 trade-off: 수동적인 요약 읽기보다 느리고 불편하지만, 무엇을 실제로 모르는지 드러나고 장기 기억과 전이 여부를 확인하기 쉽다.

## 튜터 동작 가설

1. 첫 답을 대신 작성하지 않는다.
2. 한 번에 질문 하나만 한다.
3. 답변 뒤에는 전체 요약 대신 사실 오류와 중요한 누락만 짚는다.
4. 정의 암기보다 선택 조건과 실패 상황을 묻는다.
5. 원래 자료와 표면이 다른 문제를 내서 전이를 확인한다.
6. `1 → 3 → 7 → 14 → 30일` 간격으로 다시 설명하게 한다.

## 다음 회상 질문

> AI에게 처음부터 요약을 맡기는 방식과, 내가 먼저 회상한 뒤 AI에게 피드백을 받는 방식은 실제 학습 행동에서 무엇이 다른가?

## 블로그 원재료

- 독자가 겪을 문제: 기술 영상을 많이 봤지만 면접이나 설계 대화에서 말이 이어지지 않음
- 글의 중심 주장 후보: AI는 노트 작성기보다 내 설명을 공격하는 튜터일 때 학습에 더 유용하다.
- 보여줄 비교: `AI 요약을 읽은 기록`과 `첫 회상 → 피드백 → 재답변`이 남은 기록
- 필요한 추가 검증: 실제 기술 주제 하나로 여러 차례 복습한 전후 답변, 기억 실패 사례, 변형 문제 적용 결과
