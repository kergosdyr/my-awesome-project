# C008 — 약속한 날짜 안에 택배 보내기

Day8 · Coding30분 / Minimum15분. [과제 목록](README.md)

1. **문제:** 택배 상자를 받은 순서대로 보내야 한다. 하루 무게 한도를 얼마로 잡아야 약속한 날짜 안에 전부 보낼까?
2. **이유:** C007은 정렬된 배열에서 위치를 찾았다. 이번에는 배열에 없는 ‘가능한 한도’ 중 가장 작은 값을 찾는다.
3. **개념:** 가능 여부 판단, 경계 탐색, 큰 합계를 위한 long.
4. **완료:** 최소 한도를 구하고 입력을 보존한다. 어느 후보들을 제외할 수 있는지 설명한다.

## 할 일

[ShippingCapacity.minimumCapacity](../../coding/src/main/java/challenge/coding/ShippingCapacity.java)를 구현한다. 입력은 상자별 무게와 배송 기한 days, 반환값은 모든 날에 공통으로 적용할 최소 무게 한도(long)다. 상자를 쪼개거나 순서를 바꾸지 않는다. 하루에 여러 상자를 보낼 수 있고 기한보다 일찍 끝내도 된다.

| 무게 / days | 결과 | 가능한 배송 |
| --- | --- | --- |
| [1,2,3,4,5] / 3 | 6 | [1,2,3] / [4] / [5] |
| [3,2,2,4,1,4] / 3 | 6 | [3,2] / [2,4] / [1,4] |
| [5,1,2] / 1 | 8 | 하루에 전부 |
| [5,1,2] / 3 | 5 | [5] / [1,2], 이틀만 써도 됨 |

길이1~200,000, 각 무게1~1,000,000,000, days1~길이. 잘못된 입력 검증은 제외한다. 입력 변경 금지. 합계는 int를 넘을 수 있다.

처음에는 작은 예를 손으로 계산하고 느려도 맞는 풀이를 만든다. 다음으로 ‘한도6으로 가능하면7은 어떨까?’를 생각한다. 목표 O(n log S) 시간·O(1) 추가 공간(S는 무게 합). 공개8개 통과만으로 복잡도까지 입증되지는 않는다.

```sh
./gradlew :coding:test --tests '*ShippingCapacityTest'
# Minimum은 minimum 태그의3개만
./gradlew :coding:test --tests '*ShippingCapacityTest' -Pminimum
```

제출: 첫 접근 / 버린 후보가 답일 수 없는 이유 / 시간·공간 복잡도 / 직접 만든 반례 하나 / 실제 시간·도움 범위. 구현 해답은 아직 제공하지 않았다.


## 구현 확인 · 2026-09-17

해답 설명 후 사용자 구현을 확인했다. 최대 무게~합계 탐색, 날짜 계산, left<right 종료 조건과 long 합계로 공개8/8 통과했다. 사용자는 코딩 과제를 마무리하겠다고 했으며 독립 이진 탐색 도출로 평가하지 않는다.
