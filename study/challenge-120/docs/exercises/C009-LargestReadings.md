# C009 — 응답 시간 중 가장 큰 k개 고르기

Day9 · Coding30분 / Minimum15분. [과제 목록](README.md)

1. **문제:** 하루 응답 시간 기록에서 가장 느렸던 k건을 큰 값부터 보여 준다.
2. **상황:** 운영자가 하루 응답 시간 기록 중 가장 느렸던 k건을 확인하려 한다.
3. **확인할 조건:** 중복 기록을 유지하고 입력 배열을 변경하지 않는다.
4. **완료:** 정확한 k개와 입력 보존, 기본 풀이와 최적화 비용 설명, 직접 만든 반례 하나.

[직접 구현: LargestReadings.topK](../../coding/src/main/java/challenge/coding/LargestReadings.java). readings에서 큰 값 k개를 새 int[]에 내림차순으로 반환한다. 원본 배열은 바꾸지 않는다. 동일한 값도 별개 기록이므로 제거하지 않는다. 기록 자체의 ID나 원래 순서는 반환하지 않는다.

| 입력 / k | 결과 | 설명 |
| --- | --- | --- |
| [4,9,1,7,5] / 3 | [9,7,5] | 가장 큰3건 |
| [8,2,8,5] / 3 | [8,8,5] | 8이 두 번 등장하면 두 건 |
| [7] / 1 | [7] | 한 건뿐 |
| [1,5,3] / 3 | [5,3,1] | 전체를 고를 수도 있음 |

길이1~200,000, 값0~Integer.MAX_VALUE, k는1~길이. null·잘못된 입력 검증은 제외한다. 공개 테스트8개와 기본3개 필터를 제공한다. 설치나 테스트 작성은 할 일이 아니다.

풀이 방법은 직접 선택한다. 기본3개 검사 또는 전체8개 검사로 결과를 확인할 수 있다.

최적화 목표는 O(n log(k+1)+k log k) 시간·O(k) 추가 공간이다. 정확성 통과와 이 목표 달성은 분리해서 기록한다. 큰 입력 테스트는 결과만 검사하며 시간 제한으로 알고리즘을 강요하지 않는다.

```sh
./gradlew :coding:test --tests '*LargestReadingsTest'
./gradlew :coding:test --tests '*LargestReadingsTest' -Pminimum
```
